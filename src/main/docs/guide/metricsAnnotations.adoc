You can use the Micrometer `@Timed` and `@Counted` annotations on any bean method by adding the `micronaut-micrometer-annotation` dependency to your annotation processor classpath:

dependency:micronaut-micrometer-annotation[groupId="io.micronaut.micrometer", scope="annotationProcessor"]

The annotation processor dependency is required so Micronaut can create the AOP proxy for `@Timed` and `@Counted`.
Without it, the annotations remain on the method, but no interceptor runs and no meter is recorded.

How the result of an invocation is measured depends on the return type of the method:

* Synchronous methods are timed and counted when the method returns or throws.
* Methods returning a `CompletionStage`, and Kotlin `suspend` functions, are timed and counted when the stage completes. The `exception` tag uses the cause of a `CompletionException` or `ExecutionException`.
* Reactive methods (for example `Mono`, `Flux` or `Publisher`) are timed from subscription until the publisher completes, errors or is cancelled, once for each subscription. `@Timed` records a cancelled subscription with the tag `exception=CancellationException`. `@Counted` does not count it. A publisher that is never subscribed records nothing.
* A method that throws before returning its `CompletionStage` or publisher is recorded as a failure.

`@Counted(recordFailuresOnly = true)` only counts failures, whatever the return type. `@Timed(longTask = true)` records a `LongTaskTimer` that tracks in-flight invocations instead of a `Timer`.

=== Tags from arguments and results

Micrometer's `@MeterTag` annotation (`io.micrometer.core.aop.MeterTag`, repeatable with `@MeterTags`) adds tags to the meters of `@Timed` and `@Counted` methods:

* On a parameter, the tag value is computed from the argument. Annotations on the parameters of an implemented interface method are also applied.
* On the method, the tag value is computed from the result: the return value, the completed value of a `CompletionStage` or Kotlin `suspend` function, or the value of a single result publisher such as a `Mono`. The value is empty when the invocation fails, and for publishers that can emit several values. A `@Timed(longTask = true)` long task timer only has the parameter tags, because the result is not known when it starts.

The value is computed in this order of precedence:

. `resolver`: a `io.micrometer.common.annotation.ValueResolver`. The bean of that type is used, or the class is instantiated when it is not a bean.
. `expression`: a Micronaut evaluated expression (`#{...}`). It is compiled with your application and evaluated for each invocation, without reflection. On the method, the arguments are available by name. On a parameter, Micronaut only gives the expression `this`, the environment and the beans, not the arguments. Use a method-level tag to compute a value from an argument.
. `expression` without `#{...}`: it is passed, with the argument or result, to the `io.micrometer.common.annotation.ValueExpressionResolver` bean. Micronaut does not provide one. Without such a bean the value is empty, and an error is logged.
. Otherwise `toString()` of the argument or result. `null` becomes an empty string.

[source,java]
----
@Timed("orders.lookup")
@MeterTag("status")                                           // <1>
@MeterTag(key = "items", expression = "#{ #order.items().size() }") // <2>
OrderStatus lookup(@MeterTag("tenant") String tenant,        // <3>
                   @MeterTag(key = "region", resolver = RegionResolver.class) Order order) { // <4>
    ...
}
----
<1> The `toString()` of the returned `OrderStatus`.
<2> A compile-time checked expression evaluated against the arguments.
<3> The `toString()` of the argument.
<4> The `RegionResolver` bean.

When several `@MeterTag` annotations use the same key, the first one wins. The `exception` tag, and the `result` tag of `@Counted`, take precedence over a `@MeterTag` with the same key. Methods without `@MeterTag` do no extra work per invocation.
